# Open-source motion options for RecipeFix

Checked 29 October 2026 using official repositories, model cards, license files and provider documentation. **Research only: no models downloaded, packages installed, generation performed, accounts connected or money spent.** PR115’s film remains a founder-rejected baseline.

The useful open route is an art-directed image → a short image-to-video shot → editing with real food footage. A NotebookLM clone alone does not provide that visual engine. My recommendation is **Wan2.2 TI2V-5B for the cleanest permissive video-model trial on suitable rented NVIDIA hardware**, with **LTX 2.5 Fast as the stronger integrated generation/editing candidate if its custom license fits**. For this Mac, the **community LTX 2.3 MLX int4 port** is the most relevant later local-motion experiment; its reported memory floor is lower than the official Desktop app’s, but fit, speed and food quality are untested here. **FLUX.2 klein 4B is a plausible local style-frame experiment, not a video solution.** These are research judgments, not watched food-quality benchmark results.

This Mac actually reports **Apple M4 Pro, 24GiB unified RAM, macOS 27.0.1** (`sysctl -n hw.memsize machdep.cpu.brand_string`; `sw_vers -productVersion`). There is no NVIDIA/CUDA device assumed. Unified RAM is not equivalent to the same quantity of dedicated CUDA VRAM. `mlx` is not importable in the current `/Users/isaacmineo/.pyenv/versions/3.12.9/bin/python3`; other isolated environments were not audited.

**A concrete local Mac route, with limits:** author-maintained [dgrauet/ltx-2-mlx](https://github.com/dgrauet/ltx-2-mlx) is a native Metal/MLX T2V/I2V implementation. Its **code is MIT**, while [converted 2.3 weights retain the LTX community license](https://huggingface.co/dgrauet/ltx-2.3-mlx-q4). The author reports 16GB minimum for int4, or low-RAM streaming, so this is materially more relevant to 24GiB than the official Desktop app. This is a community port, not a Lightricks-certified Mac benchmark; [its maturity document](https://github.com/dgrauet/ltx-2-mlx/blob/main/docs/PIPELINE_MATURITY.md) separates stable generation from beta/experimental editing paths. Do not interpret README “~12GB” as the complete download: current [weight metadata](https://huggingface.co/api/models/dgrauet/ltx-2.3-mlx-q4?blobs=true) totals **59.69GB** across alternative transformers/LoRAs. A single distilled transformer plus connector, video/audio VAEs, vocoder and 2× upscaler subtotal about **20.48GB**, before separately resolved text-encoder assets. That is a component subtotal, **not a verified minimum installation manifest**. No Mac runtime or accepted-shot quality was tested.

**Current release cross-check:** Wan2.2 is a 2025 permissive baseline, not a claim to be today’s best-looking open-weight system. **MiniMax H3 is real/current**, with [an official repository](https://github.com/MiniMax-AI/MiniMax-H3) and [official weights](https://huggingface.co/MiniMaxAI/MiniMax-H3). Its open H3-Base produces 768p; Context-IR is hosted/not released, and the 2K result uses a separate regeneration stage. Crucially, [its August 2026 license](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/LICENSE) excludes **the United States**, EU, UK and South Korea; default open-weight use is therefore not an available route on this Mac without separate authorization. The publisher describes globally available hosted API access as a different route. A leaderboard’s “open weights” label does not establish unrestricted local/commercial access.

**Runners are separate from models.** [ComfyUI](https://github.com/Comfy-Org/ComfyUI) is GPL 3 graph-based orchestration with Apple Silicon installation support. [DiffSynth-Studio](https://github.com/modelscope/DiffSynth-Studio) is an Apache 2 diffusion engine with disk/RAM/VRAM offloading. They can make a selected model reproducible; installing either does not supply cinematic taste, remove a checkpoint’s license, turn CUDA requirements into a verified Mac workflow, or make repeated sampling free. Halyard should retain source truth/editing/review; do not build another orchestration layer before a model produces a visibly better shot.

**NotebookLM-like tools address different work.** [Open Notebook](https://github.com/lfnovo/open-notebook) (MIT) organizes sources, citations, contextual chat and multi-speaker podcasts. [Podcastfy](https://github.com/souzatharsis/podcastfy) (Apache 2) generates conversational audio. [Presenton](https://github.com/presenton/presenton) (Apache 2 core) creates editable PPTX/PDF presentations. They can support research, scripts or storyboards; their documented core features do not replace a cinematic motion model. Conversely, [notebooklm-py](https://github.com/teng-lin/notebooklm-py) is an MIT **unofficial client for Google’s hosted service**, including video features; it is not an open/local reproduction of Google’s model stack or an entitlement to a paid feature. No wrapper/account experiment was run.

**Budget reality.** Free weights are not free accepted shots. Runpod’s current official pricing page lists RTX 4090 Pods at **$0.89/hour**; a hypothetical 9-minute inference costs about **$0.13 raw GPU time**, before setup/model transfer, storage, idle time, failures and selection. This is arithmetic using a list price and the publisher’s timing—not a quote or measured cost per usable food clip. Short occasional trials can fit a thin budget; leaving one instance running for a day costs about $21.36 before extras. No rental is authorized or started. [Official current price](https://www.runpod.io/pricing)

**Choice for the next watched comparison:** favor I2V from one strong, rights-cleared frame over broad T2V exploration; that is an editorial inference about controlling subject/lighting continuity, not a guarantee of motion quality. Compare one 3–5s generated hero against the already licensed real pineapple-cutting footage. Inspect knife/fruit continuity, texture, believable contact and actual subject movement. A generated gelatin/fruit shot remains an illustration, never proof of a performed experiment. Notebook cloning or model integration should wait for that visual result.

Separate checkpoint variants/formats are alternatives, not all required together. No claim of a food-specific quality winner has been established by this research.
